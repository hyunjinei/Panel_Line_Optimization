# Codex Prompt: Implement CA-CJH-Insertion for Shipyard Panel-Line Scheduling

Repository:
hyunjinei/Panel_Line_Optimization

Purpose:
Implement a new heuristic method for IJNAOE-style experiments by extending the existing PFSP Cosine–Jaccard Heuristic (CJH) to the shipyard panel-line scheduling problem.

The main method must preserve the identity of the original CJH:
- It must be an NEH-style constructive insertion heuristic.
- It must sort candidate blocks using a Cosine–Jaccard global priority.
- It must insert each block into all possible positions of the current partial sequence.
- It must evaluate each tentative insertion using the existing DES / constraint / bay-assignment environment.
- It must choose the best insertion position using a constraint-aware lexicographic objective.

This task is NOT about reinforcement learning.
Do NOT modify PPO training, self-labeling training, pointer-network architecture, policy loss, reward design, or RL model files.
The existing learning-based scheduler may be used only as a comparison baseline, not as part of this method.

============================================================
0. Background and Required Interpretation
============================================================

This repository contains a panel-line scheduling environment where the problem is:
- determine the block input sequence,
- assign each block to a downstream bay after common upstream processes,
- satisfy operational constraints,
- minimize constraint violations and makespan.

The existing presentation / paper materials are only for understanding the problem:
- They explain the panel-line scheduling problem, constraints, DES environment, action masking, and evaluation metrics.
- Do NOT copy or modify the self-labeling / RL algorithm for this task.

The proposed method in this task is a heuristic:

    CA-CJH-Insertion
    Constraint-Aware Cosine–Jaccard Insertion Heuristic

It adapts the PFSP CJH idea to panel-line scheduling.

Key conceptual mapping:

PFSP-CJH:
    job = processing-time vector
    global priority = cosine + Jaccard-normal similarity to robust baseline
    insertion evaluation = makespan - alpha * local-window similarity

Panel-line CA-CJH:
    block = production-feature vector
    global priority = cosine + Jaccard-normal similarity to robust baseline
    insertion evaluation = DES-based hard violation, soft violation, makespan, local-window similarity, longi balance

Important terminology:
- Cosine is production-feature / process-load shape alignment.
- Jaccard-normal is normal-load coverage / load regularity.
- Local-window similarity is local flow smoothing.
- Do NOT describe Jaccard as bottleneck overlap.
- Do NOT implement Jaccard as bottleneck overlap unless an explicit high-load set is separately implemented. For this task, do not implement bottleneck overlap.

2. Main Algorithm to Implement
============================================================

Implement the main method:

    CA-CJH-Insertion

Core procedure:

Input:
- blocks
- metadata
- existing DES / assembly environment
- parameters:
    trim_ratio gamma
    w_cos
    w_jac
    alpha
    feature_mode
    normal_scope
    evaluation_mode
    objective_mode

Output:
- final block sequence
- existing deterministic bay assignments
- makespan
- hard violation count
- soft violation count or violation score
- longi balance
- runtime
- detailed candidate/insertion trace

Algorithm:

1. Build a production-feature vector x_b for every block b.
2. Normalize feature vectors.
3. Compute a robust baseline vector using trimmed mean.
4. Compute normal feature ranges using trimmed standard deviation.
5. For every block b:
   5.1 Compute Cos(b): production-feature shape alignment.
   5.2 Compute J(b): Jaccard-normal normal-load coverage / load regularity.
   5.3 Compute S_global(b) = w_cos * Cos(b) + w_jac * J(b).
6. Sort blocks in descending order of S_global(b).
7. Initialize partial sequence pi = empty.
8. For each block b in the sorted priority list:
   8.1 For every insertion position ell in {0, ..., len(pi)}:
       - Create tentative sequence pi_candidate = insert b into pi at ell.
       - Evaluate pi_candidate with the existing DES / constraint / bay-assignment logic.
       - Compute:
           H(pi_candidate): hard violation count or hard infeasibility indicator
           V(pi_candidate): soft violation count / score
           Cmax(pi_candidate): makespan or partial makespan
           Delta_L(pi_candidate): longi bay imbalance
           S_loc(b, ell): local-window Cosine–Jaccard smoothing score
       - Build insertion key:
           objective_mode = "cost":
               key = (
                   H(pi_candidate),
                   V(pi_candidate),
                   Cmax(pi_candidate) - alpha * S_loc(b, ell),
                   Delta_L(pi_candidate)
               )

           objective_mode = "lexicographic":
               key = (
                   H(pi_candidate),
                   V(pi_candidate),
                   Cmax(pi_candidate),
                   -S_loc(b, ell),
                   Delta_L(pi_candidate)
               )

       - Smaller key is better.
   8.2 Insert b at the position ell* with the best key.
9. Return the final sequence and metrics.

Main default:
- objective_mode: "cost"
because this preserves the original CJH identity:
    cost = makespan - alpha * local-window similarity
but extended with hard/soft constraint priority.

3. Mathematical Definitions to Implement
============================================================

For each block b, define production-feature vector:

    x_b = [x_{b,1}, ..., x_{b,D}]

Default feature_mode must be:

    process_only

where x_b contains only the 8 processing times of the block.

Why:
- This most closely preserves the original PFSP-CJH identity.
- The original CJH is based on processing-time vectors.
- Additional shipyard features can be added in ablation.

Also support optional feature modes:

    process_plus_core:
        8 processing_times
        total processing time
        seam_count
        c_seam_count
        width
        longi_count

    augmented:
        process_plus_core
        length
        min_thickness
        max_thickness
        main_plate_count
        curved_plate_count
        has_curved_plate
        is_high_seam_block
        material_ready
        assembly_start slack
        max_start_date slack
        one-hot assembly_type
        one-hot port_starboard
        one-hot workshop_type
        one-hot material_type

Use safe fallback values:
- missing numeric -> 0.0
- missing bool -> 0.0
- missing categorical -> all-zero one-hot
- missing date/slack -> 0.0

Normalize feature matrix:
    x_tilde_{b,d} = (x_{b,d} - min_d) / (max_d - min_d + epsilon)

Compute baseline:
    x_B,d = TrimMean_b(x_tilde_{b,d}; gamma)

Compute trimmed std:
    sigma_d = TrimStd_b(x_tilde_{b,d}; gamma)

Normal range:
    R_d = [x_B,d - sigma_d, x_B,d + sigma_d]

Cosine:
    Cos(b) = dot(x_tilde_b, x_B) / (||x_tilde_b||_2 * ||x_B||_2 + epsilon)

Normal set:
    A(b) = {d | x_tilde_{b,d} in R_d}

Jaccard-normal:
    J(b) = |A(b)| / D

Global CJH score:
    S_global(b) = w_cos * Cos(b) + w_jac * J(b)

Local window for insertion:
For partial sequence pi_t and inserting block b at position ell:

    W_t(b, ell) =
        {b}, if t = 0
        {b, pi_1}, if ell = 0 and t > 0
        {pi_ell, b, pi_{ell+1}}, if 0 < ell < t
        {pi_t, b}, if ell = t and t > 0

Local average vector:
    x_loc(b, ell) = average normalized feature vector of blocks in W_t(b, ell)

Local cosine:
    Cos_loc(b, ell) = dot(x_loc, x_B) / (||x_loc||_2 * ||x_B||_2 + epsilon)

Local Jaccard-normal:
    J_loc(b, ell) = number of dimensions where x_loc,d is in R_d divided by D

Local-window similarity:
    S_loc(b, ell) = w_cos * Cos_loc(b, ell) + w_jac * J_loc(b, ell)

Insertion cost:
    G(pi_t^{b,ell}) = Cmax(pi_t^{b,ell}) - alpha * S_loc(b, ell)

Constraint-aware insertion key:
    key_cost = (
        H(pi_t^{b,ell}),
        V(pi_t^{b,ell}),
        G(pi_t^{b,ell}),
        Delta_L(pi_t^{b,ell})
    )

Hard constraints:
- Do not bypass existing hard constraints.
- If the environment reports a hard violation, H must be > 0.
- If H > 0, the insertion should be dominated by any H = 0 insertion.

Soft constraints:
- Soft violations may be allowed through the existing relaxation mechanism.
- They should be counted in V.
- Lower V is preferred before makespan.

Bay assignment:
- Do not invent a new bay assignment rule.
- Use the existing deterministic bay assignment / routing logic.
- CA-CJH chooses sequence; existing environment assigns bay.

============================================================

Do not use stepwise candidate-pool dispatching as the main method.

    CA-CJH-Stepwise

where at each decision step the method ranks only the current candidate pool.

    CA-CJH-Insertion

    CA-CJH-Stepwise or CA-CJH-Dispatch

- If Stepwise is implemented, it should be clearly marked as a fast dispatching variant.
- Do not confuse it with the main method.
