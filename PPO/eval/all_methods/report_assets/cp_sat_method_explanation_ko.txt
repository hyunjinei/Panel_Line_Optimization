# [AGENT-ADD] CP-SAT 비교 알고리즘 설명 자료

CP-SAT 비교 알고리즘은 GA와 같은 비교 대상 알고리즘이다.
목적은 RL, 휴리스틱, GA와 같은 문제 인스턴스에서 다른 방식으로 블록 투입 순서와 Bay 배정을 만든 뒤, 동일한 PBS 평가 경로로 결과를 비교하는 것이다.

1. 무엇을 풀어내는가

CP-SAT는 각 블록의 순서를 하나의 순열로 결정한다.
그리고 각 블록을 35A 또는 36B Bay 중 하나에 배정한다.

즉 결과는 다음 두 가지다.

- 블록 투입 순서
- 블록별 Bay 배정

2. 공정 구조

PBS 공정은 블록마다 8개 공정으로 구성된다.

- 공통 공정 5개
- Bay 분기 공정 3개

공통 공정은 모든 블록이 하나의 연속 라인을 같은 순서로 통과한다.
Bay 분기 공정은 35A와 36B로 나뉜 뒤, 같은 Bay에 배정된 블록끼리만 같은 장비 순서를 공유한다.

따라서 CP-SAT 모델 안에는 다음 구조가 들어간다.

- 모든 블록은 서로 다른 순서 위치를 가진다.
- 공통 5개 공정은 정해진 블록 순서를 따른다.
- 분기 3개 공정은 같은 Bay 안에서만 정해진 블록 순서를 따른다.
- 35A와 36B는 서로 독립된 분기 라인처럼 계산된다.

3. Bay 제약

CP-SAT 안에는 대표적인 Bay 하드 규칙을 직접 넣는다.

- 폭이 21m를 초과하는 블록은 36B로 보낸다.
- 작은 P/S 쌍은 36B로 보낸다.

이 규칙은 기존 Bay 배정 로직의 핵심 물리 규칙과 맞춘 것이다.

4. 후보 생성 목적 함수

CP-SAT의 내부 목적 함수는 후보를 빠르게 만들기 위한 목적 함수다.
기본 모드는 빠른 후보 생성 방식이다.
이 방식에서는 여러 가지 CP-SAT 후보를 만든다.

예시는 다음과 같다.

- 긴 작업 우선 후보
- 짧은 작업 우선 후보
- 심수 많은 작업 우선 후보
- 심수 적은 작업 우선 후보
- 폭이 큰 작업 우선 후보
- 론지 부하를 고려한 후보
- 기존 날짜 순서에 가까운 후보

각 후보는 CP-SAT가 순서와 Bay 배정을 만든다.
Bay 배정에서는 35A와 36B 분기 부하가 너무 한쪽으로 쏠리지 않도록 보조 목적을 둔다.

5. 최종 평가는 기존 평가기와 동일하다

CP-SAT가 만든 순서와 Bay 배정은 그대로 최종 답으로 끝나지 않는다.
그 결과를 기존 PBS 스케줄러에 다시 넣는다.

이때 다음 방식으로 재생한다.

- forced_prefix_block_ids: CP-SAT가 만든 블록 순서
- manual_bay_assignments: CP-SAT가 만든 35A/36B 배정

그리고 기존 final audit 경로에서 makespan, 제약 위반 수, 상세 공정 CSV를 다시 계산한다.

따라서 비교표에 들어가는 최종 makespan과 제약 위반 수는 GA, RL, 휴리스틱과 같은 평가 기준에서 나온 값이다.

최종 선택 기준도 GA/RL과 맞춘다.

1. 누락 블록 수
2. primary violation 수
3. makespan
4. raw violation 수

즉 CP-SAT도 최종적으로는 제약 위반을 makespan보다 먼저 본다.

6. GA와의 차이

GA는 여러 후보 순서를 만들고, 후보마다 기존 스케줄러로 평가한 뒤 가장 좋은 후보를 고른다.
CP-SAT는 수학 모델 안에서 순서와 Bay 배정을 직접 만든 뒤, 후보별로 기존 스케줄러에서 다시 평가한다.

정리하면 다음과 같다.

- GA: 후보 생성과 반복 평가 중심
- CP-SAT: 제약 모델 기반 탐색 중심
- 둘 다 최종 평가는 기존 PBS 평가기로 통일
- 둘 다 최종 선택은 제약 위반을 makespan보다 먼저 봄

7. 발표에서 강조할 말

CP-SAT baseline은 단순 정렬 휴리스틱이 아니라, PBS의 공통 공정, Bay 분기, 블록 순서, Bay 배정을 하나의 제약 모델로 옮긴 비교 알고리즘이다.
다만 논문 비교 지표는 항상 기존 PBS final audit 결과를 사용하므로, RL, 휴리스틱, GA, CP-SAT가 같은 기준에서 비교된다.
