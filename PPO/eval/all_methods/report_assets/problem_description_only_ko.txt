[AGENT-ADD] 발표용 문제 정의 설명

파일 목적
이 문서는 방법론 설명 없이, Panel-Line Scheduling 문제가 무엇인지 설명하기 위한 발표용 문제 정의이다.
RL, 휴리스틱, LLM, 학습 방법은 설명하지 않는다.


1. 문제 배경

조선소 패널 라인에서는 여러 개의 블록이 하나의 생산 라인에 순서대로 투입된다.
각 블록은 여러 공정을 차례로 거치며, 모든 블록이 끝나는 데 걸리는 전체 시간이 생산 계획의 중요한 지표가 된다.

하지만 블록마다 크기, 심수, 론지 수, P/S 쌍 여부, 자재 준비 상태, 조립 착수 기준일이 다르다.
따라서 단순히 아무 순서로 투입하면 특정 날짜의 작업량이 초과되거나, 특정 베이에 작업이 몰리거나, P/S 순서가 깨지거나, 공정 대기 시간이 커질 수 있다.

이 문제는 여러 블록을 어떤 순서로 투입하고, 공통 공정 이후 어느 베이에 보낼지를 결정하는 생산 스케줄링 문제이다.


2. 블록과 공정 구조

각 블록은 여러 개의 공정을 순서대로 거친다.
이 생산 라인은 크게 두 부분으로 나뉜다.

첫째, 공통 공정이다.
모든 블록은 먼저 같은 공통 라인을 통과한다.
예를 들어 공정 1부터 공정 5까지는 블록이 어느 베이로 갈지와 관계없이 같은 흐름을 따른다.

둘째, Bay divide 이후의 분기 공정이다.
공통 공정을 지난 블록은 35A 또는 36B 중 하나의 베이로 배정된다.
그 뒤의 후속 공정은 배정된 베이에서만 진행된다.

즉, 한 블록이 35A에 배정되면 그 블록은 36B에서는 작업하지 않는다.
반대로 한 블록이 36B에 배정되면 그 블록은 35A에서는 작업하지 않는다.


3. Bay divide 예시

예를 들어 블록 1, 블록 2, 블록 3이 순서대로 투입된다고 하자.

블록 1:
- 공통 공정 1~5를 먼저 통과한다.
- 이후 35A 베이에 배정된다.
- 따라서 블록 1의 후속 공정은 35A에서만 진행된다.
- 이때 36B는 블록 1을 작업하지 않는다.

블록 2:
- 블록 2도 공통 공정 1~5를 먼저 통과한다.
- 이후 36B 베이에 배정될 수 있다.
- 그러면 블록 2의 후속 공정은 36B에서만 진행된다.
- 이 경우 35A는 블록 2를 작업하지 않는다.

블록 3:
- 블록 3도 공통 공정을 지난 뒤 35A 또는 36B 중 하나로 배정된다.
- 어느 베이에 배정되는지에 따라 해당 베이의 대기 시간과 전체 완료 시간이 달라진다.

따라서 같은 블록 순서라도 Bay 배정이 달라지면 최종 완료 시간이 달라질 수 있다.


4. 공정 대기 문제

각 블록은 앞 공정이 끝나야 다음 공정을 시작할 수 있다.
또한 같은 공정이나 같은 베이가 이미 다른 블록을 처리 중이면 기다려야 한다.

예를 들어 블록 1이 35A에서 후속 공정을 오래 수행 중이면, 다음에 35A로 들어가야 하는 블록은 기다릴 수 있다.
하지만 36B가 비어 있다면, 36B에 배정된 다른 블록은 더 빨리 후속 공정을 시작할 수 있다.

즉 전체 완료 시간은 단순히 블록별 작업 시간을 더한 값이 아니다.
공통 공정의 흐름, 35A와 36B의 분기, 각 베이의 대기 시간이 함께 영향을 준다.


5. 제약 조건이 생기는 이유

현실 생산에서는 모든 블록을 자유롭게 배치할 수 없다.

예를 들어 다음과 같은 제약이 존재한다.
- 하루에 처리할 수 있는 심수에는 한계가 있다.
- 하루에 투입할 수 있는 블록 수에는 한계가 있다.
- P/S 쌍은 순서와 연속성이 중요하다.
- 폭이 큰 블록은 특정 베이에 더 적합할 수 있다.
- 론지 수가 많은 블록은 베이 부하에 큰 영향을 준다.
- 같은 베이에 블록이 연속으로 몰리면 위험한 패턴이 생길 수 있다.
- C/Seam, 곡판, 고심수 블록은 간격을 두고 배치해야 할 수 있다.
- 조립 착수 기준일보다 너무 이르거나 늦은 투입은 문제가 될 수 있다.

이 제약들은 실제 생산 현장의 품질, 안전, 작업 가능성, 작업 균형을 반영한다.


6. 문제에서 결정해야 하는 것

이 문제에서 결정해야 하는 것은 크게 두 가지다.

첫째, 블록 투입 순서이다.
남아 있는 블록 중 어떤 블록을 다음에 공통 라인에 넣을지 정해야 한다.

둘째, Bay 배정이다.
공통 공정을 지난 블록을 35A로 보낼지, 36B로 보낼지 정해야 한다.

이 두 결정은 서로 독립적이지 않다.
어떤 블록을 먼저 넣느냐에 따라 이후 베이 대기 시간이 달라지고, 어떤 베이에 배정하느냐에 따라 다음 블록의 시작 가능 시간이 달라진다.


7. 문제의 목표

이 스케줄링 문제의 목표는 다음과 같다.

첫째, 전체 블록이 모두 완료되는 시간을 줄이는 것이다.
이를 makespan이라고 한다.

둘째, 실제 생산 제약 위반을 줄이는 것이다.
단순히 빨리 끝나는 순서만 찾는 것이 아니라, 생산 현장에서 실행 가능한 순서를 찾아야 한다.

셋째, 35A와 36B의 작업 부하가 한쪽으로 과도하게 쏠리지 않도록 하는 것이다.
Bay divide 이후의 부하 균형이 나빠지면 한쪽 베이는 대기하고 다른 쪽 베이는 놀게 되어 전체 시간이 길어질 수 있다.


8. 발표용 한 문장 정의

Panel-Line Scheduling 문제는 여러 블록을 공통 공정에 어떤 순서로 투입할지 결정하고, 공통 공정 이후 각 블록을 35A 또는 36B 중 하나의 베이에 배정하여, 전체 완료 시간과 생산 제약 위반을 동시에 줄이는 문제이다.


9. 발표 그림에 넣을 핵심 장면

그림에서는 다음 장면을 보여주면 된다.

Block sequence:
Block 1 -> Block 2 -> Block 3

Common process:
모든 블록이 공통 공정 1~5를 차례로 통과

Bay divide:
공통 공정 이후 두 갈래로 나뉨

35A:
Block 1 작업

36B:
Block 2 작업

중요한 표현:
Block 1이 35A에 배정되면 36B에서는 Block 1을 작업하지 않는다.
Block 2가 36B에 배정되면 35A에서는 Block 2를 작업하지 않는다.
두 베이는 서로 다른 후속 공정 분기이며, 어떤 블록을 어느 베이에 보내는지가 전체 대기 시간과 makespan을 바꾼다.
