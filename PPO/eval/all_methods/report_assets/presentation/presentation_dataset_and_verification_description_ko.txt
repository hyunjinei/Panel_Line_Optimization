# [AGENT-ADD] 발표용 CSV와 데이터 설명

이 폴더는 발표와 엑셀 그래프 작성을 위해 필요한 생성데이터 결과와 practical case 결과를 한 곳에 모은 폴더입니다.
원본 결과 파일은 report_assets 상위 폴더와 PPO/eval 각 실행 폴더에 그대로 남겨두고, 여기에는 발표용 복사본만 모았습니다.


1. 생성데이터 실험 구성

비교 방법:
- SPT
- MSF
- LPT
- GA
- Proposed

블록 수:
- 20부터 200까지 10 단위
- 20, 30, 40, 50, 60, 70, 80, 90, 100, 110, 120, 130, 140, 150, 160, 170, 180, 190, 200

크기 구간:
- Small: 20~80 블록
- Medium: 90~140 블록
- Large: 150~200 블록

분포:
- base
- ps_heavy
- sub_heavy
- mixed_ps_sub
- heavy_work
- overload


2. 생성데이터 분포 뜻

base
- 기본 생성 조건입니다.
- P/S 쌍을 추가로 많이 만들지 않습니다.
- 별판 그룹을 추가로 만들지 않습니다.
- 작업량, 크기, 두께 스케일은 기본값입니다.
- 기준 문제로 사용합니다.

ps_heavy
- P/S 쌍이 많은 문제입니다.
- P/S 관련 순서와 연속성 부담이 커집니다.
- ps_ratio가 0.10으로 설정됩니다.
- sub_ratio는 0.00입니다.

sub_heavy
- 별판 또는 소조립 그룹이 많은 문제입니다.
- 별판 통합 처리 관련 이벤트가 더 자주 생길 수 있습니다.
- sub_ratio가 0.10으로 설정됩니다.
- ps_ratio는 0.00입니다.

mixed_ps_sub
- P/S 쌍과 별판 그룹이 둘 다 많은 문제입니다.
- P/S 순서 부담과 별판 묶음 처리가 동시에 들어갑니다.
- ps_ratio와 sub_ratio가 모두 0.10입니다.

heavy_work
- 블록 자체의 작업량이 큰 문제입니다.
- 심수, tact time, 길이, 폭, 두께가 커집니다.
- 한 블록당 처리 시간이 길어지고 용량 부담이 커집니다.
- makespan과 제약 충돌을 함께 보기 위한 분포입니다.

overload
- 전체 생산 부하가 큰 문제입니다.
- util_target이 1.25로 높습니다.
- 같은 기간 안에 더 빡빡하게 블록을 넣는 상황을 나타냅니다.
- 용량 초과, 일정 밀림, 제약 충돌 가능성이 커집니다.

주의:
- sub_ratio = 0.00은 생성 단계에서 별판 그룹을 의도적으로 만들지 않는다는 뜻입니다.
- ps_ratio = 0.00은 생성 단계에서 P/S 쌍을 의도적으로 만들지 않는다는 뜻입니다.
- base는 제약이 없는 문제가 아닙니다. 용량, 베이, C/Seam, 라인, 론지 같은 기본 제약은 그대로 검사됩니다.

6. Violation 집계 기준

Primary violation
- 실제 제약 위반으로 집계하는 값입니다.
- 발표에서 "violation"이라고 말할 때 사용하는 기준입니다.

Raw event
- 검사 중 감지된 모든 이벤트입니다.
- 실제 위반과 INFO 이벤트를 모두 포함합니다.

Info event
- 정보성 이벤트입니다.
- 실제 위반으로 세지 않습니다.

Proposed practical case 결과:
- audit_primary = 0
- audit_raw = 6
- audit_info = 6
- audit_primary_constraint_ids = []
- audit_raw_constraint_ids = ["P7#1", "P7#1", "P5#17", "P5#17", "P5#17", "P5#17"]

해석:
- P7#1은 론지 A/B 부하 균형 관련 정보성 이벤트입니다.
- P5#17은 별판 통합 처리 정보성 이벤트입니다.
- Proposed의 raw event 6건은 모두 INFO이므로 실제 primary violation은 0입니다.

8. 발표용 문장 예시

생성데이터 실험에서는 블록 수 20~200 범위와 6개 분포 조건을 조합하여 SPT, MSF, LPT, GA, Proposed를 비교하였다.

분포 조건은 기본 문제, P/S 쌍 증가, 별판 그룹 증가, P/S와 별판 혼합, 작업량 증가, 전체 부하 증가를 각각 나타낸다.

Practical case에서는 원본 실적 데이터를 사용하여 각 방법의 makespan, primary violation, Bay longi 분배를 비교하였다.

Violation은 primary violation 기준으로 집계하였다. Proposed는 저장된 CSV 숫자만 사용한 것이 아니라, 원본 블록 데이터를 다시 불러오고 저장된 시퀀스와 Bay 배정, 시작 및 종료 시간을 재생하여 독립 감사로 다시 검사했다.

독립 감사 결과 Proposed의 primary violation은 0이며, raw event 6건은 모두 INFO 이벤트이므로 실제 위반에서 제외하였다.
