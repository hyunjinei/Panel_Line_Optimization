# 환경/제약/베이 흐름

이 문서는 **환경 상태 업데이트와 제약 검사의 전체 흐름**을 설명합니다.  
실시간 후보 필터링과 사후 검증을 구분해서 이해하는 것이 중요합니다.

---

## 1) 환경 핵심 흐름

```
reset()
  └─ 데이터 로드, 상태 초기화
step(action)
  ├─ 베이 배정 (bay/assigner)
  ├─ 제약 체크 (masking/core)
  ├─ 상태 업데이트 (constraints/managers)
  └─ 결과/보상 반환
```

---

## 2) 데이터 구조 요약

| 구조 | 역할 |
|---|---|
| EnhancedBlock | 블록 속성 묶음 |
| EnvironmentState | 전역 상태 |
| ConstraintViolation | 위반 기록 |
| ActionResult | 스텝 결과 |

---

## 3) 상태 업데이트 핵심 항목

- 현재 날짜/시간
- 일일 심수 사용량
- 일일 블록 수
- 작업장 누적 부하
- P/S 쌍 처리 상태
- 베이 연속 패턴
- 작업장 순서 이력

---

## 4) 실시간 검사 vs 사후 검증

| 구분 | 위치 | 특징 |
|---|---|---|
| 실시간 검사 | masking/* | 후보 필터링, 완화 적용 |
| 사후 검증 | bay/validator | 결과 스케줄 검증 |

실시간 검사는 **선택 직전**에 적용되고,  
사후 검증은 **결과 전체를 재검사**합니다.

---

## 5) reward와 score의 차이

- 환경 내부에서도 reward 계산 로직이 존재
- 학습/평가에서는 별도 score를 계산하는 구조
- 따라서 **env reward는 유지용**, **학습 score는 비교용**으로 이해

---

## 6) 캘린더 적용 흐름

- `calendar_manager`가 휴무/반일/점심 구간을 관리
- 해당 시간대는 작업 불가 시간으로 처리
- 설정 위치: `config.yaml`의 `calendar` 섹션

---

## 7) 자주 발생하는 오류 유형

1) 일일 용량 위반
   - `plan_date` 기준인지 `실제시간` 기준인지 확인 필요

2) 작업장 순서 위반
   - `masking/core.py`에서 strict_rules 적용 여부 확인

3) 베이 연속 제약 위반
   - `bay/validator`에서 사후 검증 로직 확인

4) 점심/휴무 미적용
   - calendar 설정이 runtime_config에 반영되었는지 확인
